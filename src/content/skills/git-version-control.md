## 定義

Git 追蹤文字型檔案的版本與差異。對研究工作而言，它提供可比較的存檔點、決策歷史與多人協作基礎，而不是資料備份的全部。

## 何時使用

- 修改分析程式、論文來源、設定或研究文件。
- 讓 AI 或合作者在同一工作區改檔。
- 需要找出某項結果從哪次修改開始改變。

## 快速做法

動工前確認工作區狀態；修改後逐檔看差異；把不同目的拆成小 commit；訊息說明改動與理由。推送、合併或回復前先確認不會覆蓋他人工作。

## 最低驗收標準

- [ ] 修改前已辨識未保存的既有工作。
- [ ] commit 只含本次目的相關檔案，沒有憑證與敏感資料。
- [ ] 差異已人工審查，訊息能說明研究意義。
- [ ] 可指出一個已知良好的回復點。

## 常見陷阱

不要用破壞性命令清除不屬於本次任務的修改；大型或敏感資料需另有受控儲存與版本策略。
