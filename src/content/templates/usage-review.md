## 用法

每完成一個專案或累積數週使用後執行。工具若有 `/insights` 可先看內建報告；沒有時就用這段 prompt，並把值得長期保留的結論寫回工作守則。

主對話 context 是主模型當輪可見內容的用量；總 token 是所有相關模型呼叫的累計用量，兩者不能直接當成同一數字。費用還受模型單價、輸入輸出、快取與方案影響；完成時間則包含等待、整合、查核與重做。分身可能讓主對話變短，卻增加總 token；較低成本模型也可能因重做而花更多時間。比較同類任務且都通過驗收後，再判斷分工是否值得。可參考[規劃分工的起點](../../guides/research-skills/#plan)與 [Claude Code 成本管理](https://code.claude.com/docs/en/costs)。

## 完成後你會得到什麼

三個下一次能直接採用的交辦改進、一段工作守則草稿，以及一個值得封裝或繼續觀察的重複流程。

## 不適用情境

不適合拿來評估研究成果是否正確，也不要把含個資、機密研究內容或未授權對話紀錄交給未核准服務做回顧。
