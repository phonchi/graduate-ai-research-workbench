## 研究生日常

你可能已經用 ChatGPT 改過摘要、問過統計名詞，也可能遇過這種挫折：聊到第 30 輪後，它忘了研究問題；你貼了三篇論文，它只回到第一篇；答案讀起來很完整，實際檔案卻一個也沒改。

先別急著怪模型。你很可能是拿「聊天」的用法，處理一個需要「動手」的任務。查一個定義、潤飾一段文字，Chat 很合適；整理資料夾、修改程式、執行測試、產出簡報並檢查結果，才是 Agent 的主場。

## 投影片的核心比喻

把 Agent 想成三個零件，加上一個會反覆運轉的迴圈：

- **腦（模型）**：讀懂你的話、推理與判斷下一步。
- **手（工具）**：讀檔、改檔、執行程式、搜尋資料。
- **規矩（工作守則）**：哪些檔案能碰、輸出慣例、研究紅線與完成條件。
- **迴圈**：觀察現況 → 動手做一步 → 驗證結果 → 再決定下一步。

模型多聰明不完全由你控制，但規矩可以。就像新進研究助理需要一頁入職須知，Agent 也需要知道你的資料夾結構、命名方式、驗證習慣，以及哪些資料不能外流。

## 正式工具名詞

**ChatGPT** 是對話型 AI 介面，可處理問答、整理與文字工作。**Codex、Claude Code、Gemini CLI** 這類 coding agent 則能在授權範圍內操作工作區與執行工具。不同產品能力會變，但「能否動手、能動到哪裡、做完會不會驗證」才是選工具時要看的差別。

工作守則在不同工具有不同檔名。Codex 常讀 **AGENTS.md**，Claude Code 常用 **CLAUDE.md**。概念相同：把每次都要重講的慣例寫下來。

投影片把 **subagent（分身）** 比喻成去翻完整本課本的助理：閱讀過程留在另一張桌上，只帶一頁結論回到主對話。第六單元再完整比較它與 Skill、MCP 的差異。

## 直接試一次

先拿一個不會破壞資料的小任務，請 Agent 做完整迴圈：

```text
請先觀察這個專案的檔案結構，不要修改檔案。
找出研究簡報的來源檔、產生方式與既有檢查命令，
用 5 點內回報你看到的現況，以及你會如何驗證下一次修改。
資訊不足時先問我，不要猜。
```

接著建立一頁工作守則，至少寫四件事：研究主題、常用輸出、驗證方式、不可碰的資料。例如：

```markdown
# 研究工作守則
- 回覆使用繁體中文，先講結論。
- 修改程式後執行現有測試，回報實際結果。
- 動到 3 個以上檔案前，先列出修改範圍。
- 不讀取受試者個資、憑證與未授權資料。
```

## 真實案例怎麼看

[3D 曲面與導數反例互動教材](/graduate-ai-research-workbench/cases/interactive-calculus/)展示研究者負責概念與檢查，Agent 負責前端實作；[搜尋與排序演算法動畫](/graduate-ai-research-workbench/cases/algorithm-visualization/)則把「會動」再推進到「每一步都能驗證」。研究生可把相同分工轉用到模型示意圖、分析流程 prototype 或口試展示頁。

## 先避開三個坑

1. **把所有 AI 都叫 Agent**：先確認它是否真的能讀寫檔案與執行工具。
2. **第一次就開放整個硬碟**：只授權任務需要的資料夾，先在副本練習。
3. **把「能操作」當成「能自行決定」**：研究範圍、公開程度與最後判斷仍由你負責。

## 一句帶走

**Chat 幫你想，Agent 幫你做；真正讓它可靠的，是你給的工具邊界、工作守則與驗證迴圈。**
