## 研究痛點

大量 PDF、DOCX 與講義直接塞進對話會超出上下文，也讓回答難以回到原文。研究者需要先知道「有哪些文件、哪裡可能相關」，再對少量候選段落精讀與引用。

## 授權輸入

教學示例只使用合成研究備忘錄、公開授權文件與自行建立的測試檔。處理真實資料前，需確認著作權、IRB/研究倫理、資料使用協議與雲端處理限制；不確定時保持本地處理。

## 任務規格

每份文件要保留穩定識別碼、來源檔名、類型、擷取狀態、文字路徑與基本統計。輸出至少包括逐檔 Markdown、JSONL 或 JSON 索引、快速摘要與失敗清單；任何摘要都要能回到來源檔與頁碼或段落。

## 做法

1. 先建立合成資料集與允許的檔案類型清單。
2. 以對應解析器批次擷取文字，保留錯誤而不靜默略過。
3. 建立包含路徑、字數、片段與主題提示的結構化索引。
4. 查詢時先搜尋索引，再開啟少數原文核實，來源更新後重跑擷取與索引。

## 人工檢查點

人工抽查表格、公式、腳註、頁碼與 OCR 品質，並確認摘要沒有把不同文件的主張拼成一個結論。若來源是掃描 PDF，必須標記 OCR 風險；引用前仍需回到原檔。

## 成果與證據

[`examples/synthetic-corpus`](https://github.com/phonchi/graduate-ai-research-workbench/tree/main/examples/synthetic-corpus) 實際收錄四份合成來源與一份 `index.json`；案例預覽中的 `4 / 4`、`4 records` 與索引記錄數一致。合格證據包括檔案數對得上、索引路徑可開啟，以及抽樣內容能回溯到對應的合成來源。

## 常見失敗

- 只產生向量索引，卻沒有可人工閱讀的來源對照。
- 掃描 PDF 擷取為空白，但流程仍標示成功。
- 檔案更新後沿用舊快取，造成引用版本不一致。
- 摘要保留姓名、路徑或文件屬性中的敏感資訊。

## 隱私與授權

原始檔、文字快取、索引與備份都屬同一資料治理範圍。對外展示使用合成文件，移除作者、路徑、註解與中繼資料；刪除來源時也要同步刪除衍生快取，不能只刪原檔。

## 延伸挑戰

加入內容雜湊與版本欄位以偵測過期快取，建立頁級引用定位，並以一組已知答案的合成問題評估召回率與來源追溯正確率。
