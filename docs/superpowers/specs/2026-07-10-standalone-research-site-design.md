# 研究生 AI 研究工作台獨立化設計

## 背景

目前網站內容雖已整理成課程、工具、案例與模板，但公開頁面仍顯示投影片頁碼，正文也多次以「投影片指出」或「講者所用工具」建立脈絡。這使網站像簡報伴讀頁，而不是研究生能獨立查詢、持續維護的教材。

本次改版以資料夾內多份教學簡報、教材文件與其 references 作為內部研究材料。公開網站只呈現可自足的概念、操作方法、研究案例與精選來源，不呈現簡報頁碼。

## 目標

1. 移除所有公開頁面的投影片頁碼、對照標籤與依賴講者脈絡的語句。
2. 保留六篇核心課程，新增一篇「可重現研究與 Agent 評估」。
3. 將其他簡報中可泛化的 Harness、校準、漸進式披露、安全與人機協作概念整合進既有課程。
4. 每篇課程列出 2 至 4 個直接支撐內容的研究論文、官方文件或標準來源。
5. 工具詞典改用能力與執行環境描述，避免把研究任務綁定單一產品。
6. 讓安全、案例與模板更貼近研究生命週期，而非只展示教學網站成果。

## 非目標

- 不建立完整 references 資源庫或簡報索引頁。
- 不公開簡報頁碼、內部簡報檔名或講者備課脈絡。
- 不照搬產品價格、模型上限、token 比例或其他容易過時的數字。
- 不要求模型輸出完整 chain of thought；只要求簡短理由、來源與可驗證中間產物。
- 不把教師版點擊教學或非官方自動化工具升級成核心研究基礎設施。

## 資訊架構

### 核心課程

1. **Agent 心智模型**：模型、工具、規則、環境與人的責任；補入 Centaur/Cyborg 兩種協作方式。
2. **任務規格與反問**：目標、背景、範圍、限制、格式、範例與驗收標準；產品專屬反問功能只作例子。
3. **Context 與來源閱讀**：quick notes、索引、按需取回、原文核對、長對話 checkpoint、preprint/正式版與勘誤辨識。
4. **研究工作環境**：Harness、規則檔、Git checkpoint、progress 記錄、權限與可驗證命令。
5. **驗證與獨立審查**：planner/generator/evaluator 分工、反例、重新計算、引用核對、spec drift 與停止條件。
6. **可重複工作流**：Skill、漸進式披露、從真實失敗萃取規則、盲測、校準與 skill rot。
7. **可重現研究與 Agent 評估**：environment/lockfile、raw/derived data、seed/config、log、manifest、gold tasks、人工 rubric 與錯誤分析。

七篇課程不使用同一套固定章節模板。依主題分別採比較表、診斷流程、逐步 tutorial、案例拆解、決策樹或可執行清單。

### 研究任務

維持讀文獻、寫作、程式/實驗、簡報、網站與重複流程入口，但先詢問能力需求：

- 是否需要讀寫本機檔案
- 是否需要執行命令或程式
- 是否需要依固定來源回答與引用
- 是否涉及敏感或受管制資料
- 是否需要多人協作、版本歷史或公開部署

結果列出符合能力的多個工具與下一篇建議課程，不直接推薦單一品牌。

### 工具詞典

保留現有產品、檔案、功能、協定與工作方式，但在列表上清楚分組。工具能力由單一 `canEditFiles` 擴充為 facets：

- 本機檔案存取
- 命令執行
- 固定來源引用
- 網頁或外部服務
- 背景/長時間任務
- 人工確認與權限模式
- 主要執行環境

產品頁保留 `lastVerified` 與官方入口。平台專屬功能如 `AskUserQuestion`、`/insights` 放在「平台功能」，不作通用概念的唯一名稱。

### 案例

案例分成三類並在列表顯示：

- 公開成果
- 可重跑示範
- 匿名流程重建

現有文件快取與匿名審稿案例深化研究操作紀錄；新增第七個可重現實驗案例，至少包含輸入、環境、命令、設定、輸出、驗證與失敗紀錄。教學網站與簡報案例保留，但研究生轉用不再只靠假設性條列。

### 安全與研究責任

安全頁由四條紅線擴充為：

- 資料分級：公開、實驗室內部、受 DUA/IRB 約束、受試者資料、審稿文件、secrets
- 最小權限、sandbox 與不可逆操作確認
- prompt injection 與不可信文件/網頁
- 金鑰、cookie、token 與套件安裝風險
- 引用、AI 使用揭露、作者責任與機構/期刊政策
- 公開發布、保存期限與刪除責任

## 來源模型

`slideRefs` 從 lesson、case 與 template schema 移除。課程改用一般化 `references`：

```yaml
references:
  - title: Lost in the Middle
    url: https://arxiv.org/abs/2307.03172
    type: paper
    note: 支持長 context 中資訊位置會影響取用的討論。
```

每篇課程顯示 2 至 4 個精選來源。其餘簡報與本地教材只用於內部交叉整理，不出現在公開頁面。
`type` 限定為 `paper`、`official`、`standard`、`policy` 或 `case`，以便讀者辨識證據層級。

來源優先序：

1. 原始研究論文、正式標準與政策
2. 產品官方文件或官方 repository
3. 作者公開案例
4. 社群文章只作延伸閱讀，不支撐關鍵技術斷言

發布前需重新確認所有產品文件網址與產品專屬能力。無正式來源的精確比例、成本、功能上限與內部機制不得加入。

## 頁面與互動

- 首頁將「投影片主線」改為「核心學習路徑」。
- 課程卡片顯示時間、學習成果與關鍵詞，不顯示頁碼。
- 課程側欄顯示先備概念、相關工具或可產出的研究成果。
- 模板頁只顯示用途與適用任務。
- 案例側欄顯示案例類別、可重跑性與相關工具。
- 工具列表增加能力 facets 篩選與跨工具比較提示。
- 任務頁從產品捷徑改成能力導向的決策流程。
- 保留舊網址 redirects，避免已發布連結失效。

## 測試與驗收

### 內容契約

- 7 lessons、13 tools、7 cases、7 templates。
- 公開內容不得包含「對照投影片」「投影片主線」「投影片的核心比喻」或使用者可見的 `slideRefs`。
- 每篇 lesson 有 2 至 4 個 references，且 URL、type、title 完整。
- 所有 related tool/case/lesson slug 可解析。
- 所有案例封面存在，案例類別合法。
- 工具能力 facets 與篩選值一致。

### 瀏覽器驗證

- 桌機與手機首頁、課程、工具、任務、安全、案例均無水平溢位或破圖。
- 工具能力篩選可組合、可清除，無 JavaScript 時仍可閱讀全部工具。
- 課程 references 可點擊且不造成重複名稱或可及性問題。
- 舊網址仍轉到專案 base 內的新頁面。
- Pagefind 可搜尋新課程、工具與研究實作內容。
- 主要頁面通過 axe 自動可及性檢查。

## 實作順序

1. 先更新 schema 與內容契約測試，建立失敗基準。
2. 移除公開頁面與 frontmatter 中的投影片依賴。
3. 重寫六篇課程並新增第七篇。
4. 加入精選 references，逐一用原始或官方來源確認。
5. 擴充工具能力、任務決策、安全與案例分類。
6. 更新模板與案例，加入可重現研究實作。
7. 執行 unit、Astro build、Pagefind、Playwright 與人工截圖檢查。
8. 獨立內容與程式審查通過後合併、推送並驗證 GitHub Pages。

## 完成定義

新使用者即使從未看過任何簡報，也能從研究任務或核心課程進站，理解概念、選擇工具、完成一個可驗收的研究工作流，並沿課程末尾的精選來源回到原始論文或官方文件。網站不再暴露投影片頁碼，且所有會隨產品變動的資訊都有官方來源與查證日期。
